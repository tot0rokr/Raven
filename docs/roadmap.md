# Raven 개발 마일스톤

현재 동작하는 HTTPS/noVNC, 단일 계정 인증, 세션 생성·이름 변경·삭제·명령 실행을 기반으로 웹 접속을 확장한다. 미완료 마일스톤의 명령 이름과 화면 구성은 구현 예정안이다.

- [x] M2 — 웹 doctor와 오류 진단

- [ ] M5 — 세션 안의 파일 탐색기

- [ ] M7 — 실행 상태를 유지하는 일시정지·이어하기
- [ ] M8 — 인증서 상태·내보내기·갱신
- [ ] M9 — 로그인 기기 목록과 접속 해제

## 상태 보존의 의미

세션 상태를 보존하는 방식은 네 가지이며 서로 대신하지 않는다.

- 일시정지·이어하기(M7): 컨테이너 프로세스를 메모리에 둔 채 멈췄다가 재개한다. 창·미저장 입력·프로세스 메모리를 유지하지만 RAM을 반납하지 않고 서버 재부팅에는 유지되지 않는다.
- 종료·다시 시작: 프로세스를 새로 실행한다. 파일만 남고 미저장 입력과 프로세스 메모리는 사라진다. 상태 복원으로 표시하지 않는다.
- 파일 백업·복원(M10): 세션 홈과 설정 파일을 보존한다. 프로세스 메모리는 포함하지 않는다.
- 디스크 checkpoint·복원(M11, M12): 실행 메모리와 프로세스 상태를 디스크에 기록한다. RAM 회수와 재부팅 후 복원이 목표이며 지원 여부는 M11에서 판정한다. 파일 상태도 checkpoint와 일치해야 한다.

`run --host`로 띄운 앱은 컨테이너 밖의 프로세스라서 어느 방식에도 포함되지 않는다.

## M1 — 접속 설정 저장과 status 개선

목표: 서버 포트와 브라우저 주소를 구분하고, 재시작할 때 설정을 다시 추측하거나 입력하지 않게 한다.

완료: 2026-11-02. 재검증: 2026-11-13(`c827abe`).

- 구현: `raven web configure`가 listen 주소·서버 포트·origin·SSH 안내 값을 저장하고 옵션 없는 `start`가 그 값을 쓴다. 기존 설치는 컨테이너의 실제 포트 매핑을 읽어 이전한다. `status`는 읽기만 하며 실행 중 설정과 저장 설정을 구분한다. 코드는 [raven-web](../raven-web), [service_config.py](../web/raven_web/service_config.py).
- 검증: [설정 통합 시험](../tests/web_config_e2e.py)이 초기화 전·중계 종료·포트 충돌·인증서와 맞지 않는 origin·기동 실패 복원과 재시작 후 설정·계정·인증서 보존을 확인한다. [화면 통합 시험](../tests/web_e2e.py)이 서로 다른 서버·브라우저 포트로 로그인·WSS·RFB를 확인한다. 실제 접속 PC의 SSH 인증은 자동 시험에 포함하지 않는다.
- 문서: [접속 설정 저장](./web.md#접속-설정-저장), [상태 확인](./web.md#상태-확인).

## M2 — 웹 doctor와 오류 진단

목표: 긴 Docker 명령이나 모호한 로그인 오류만 보고 원인을 추측하지 않게 한다.

완료: 2026-11-13.

- 구현: `raven web doctor`가 Docker, 게이트웨이, 이미지, 데이터 volume, 계정, 인증서, 설정, 중계, 게이트웨이→중계 경로, 실제 HTTPS 응답을 읽기만 해서 검사하고 실패마다 다음 조치를 출력한다. 데이터 volume은 [service_config.py](../web/raven_web/service_config.py)의 `inspect`로 조회하며 개인 키와 비밀번호 hash는 읽지 않는다. 웹 화면과 API는 CSRF 실패 원인, 다른 주소로 연 경우, 중계 장애, 중계가 거부한 세션 작업을 메시지와 오류 코드로 구분한다.
- 검증: [doctor 통합 시험](../tests/web_doctor_e2e.py)이 적용 대기 설정, 포트 충돌, 인증서와 맞지 않는 origin, 중계 중지·비정상 종료·runtime 디렉터리 교체, 만료 인증서, runtime 디렉터리 권한, Docker 접근 실패, 다른 uid 소유 volume을 재현해 진단과 종료 코드를 확인한다. 실행 전후 설치 상태가 같고 출력·로그에 인증 정보가 없음도 확인한다. 웹 보안 시험은 CSRF 원인별 응답, 다른 주소 안내 페이지, 중계 오류 코드, 없는 계정과 틀린 비밀번호의 같은 응답을 확인한다.
- 남은 제약: 인증서 갱신은 M8에서 한다. doctor는 접속 PC의 터널과 브라우저 주소를 볼 수 없다.
- 문서: [진단](./web.md#진단), [화면 오류](./web.md#화면-오류).

## M3 — 서비스 자동 기동과 연결 복구

목표: 서버 재부팅과 일시적인 통신 장애 뒤에 수동 복구를 반복하지 않게 한다.

- 사용자 단위 서비스로 호스트 중계와 웹 컨테이너의 시작·종료 순서를 관리하고 M1에 저장한 설정을 쓴다. 로그인 전 부팅 기동에는 user linger와 Docker 기동 순서를 확인하되 공유 Docker 데몬이나 다른 사용자의 서비스를 바꾸지 않는다.
- 중계가 비정상 종료하면 제한된 횟수로 재시작하고, 실패 원인은 doctor로 확인한다.
- 브라우저는 일시적인 연결 실패 때 지연을 늘려 재접속하며, 매번 로그인 세션을 확인하고 새 VNC 접속 정보를 받는다. 로그아웃·인증 만료·세션 삭제·사용자의 연결 종료에는 재접속하지 않는다.

완료 조건:

- 격리된 시험 호스트의 재부팅과 중계 종료 뒤 저장된 주소로 접속된다.
- 네트워크 단절 후 화면이 복구되고, 로그아웃 뒤에는 재접속하지 않는다.
- 자동 복구가 데스크톱을 임의로 재시작하지 않는다.

## M4 — 양방향 텍스트 클립보드

목표: 접속 PC와 Raven 사이에서 텍스트를 양방향으로 복사한다.

- PC의 텍스트를 세션으로 보내는 붙여넣기 패널과, 세션에서 복사한 텍스트를 PC로 가져오는 버튼을 둔다. 브라우저 권한이 없으면 텍스트 영역에서 수동으로 복사·붙여넣기한다.
- 사용자 동작으로만 전송하고 내용을 로그·URL·브라우저 저장소에 남기지 않는다. 로그아웃과 연결 종료 때 패널을 비운다.
- 범위는 텍스트다. 이미지·파일 clipboard는 다루지 않으며 M6의 파일 전송과도 별개다.

완료 조건:

- 한글·영문·여러 줄 텍스트를 양방향으로 전달하고 xterm과 세션 브라우저에서 확인한다.
- 여러 세션에 접속해도 선택한 연결의 clipboard로만 전달한다.
- 권한 거부, 연결 종료, 길이 제한 초과에서 이유를 표시하고 민감한 내용을 남기지 않는다.

## M5 — 세션 안의 파일 탐색기

목표: 파일 전송보다 먼저 데스크톱 안에서 파일을 찾아 열고 관리하게 한다.

- 가벼운 GUI 파일 관리자를 addon으로 제공한다.
- 메뉴와 런처에서 열고 홈·Downloads로 이동한다. 기본 파일 연결과 디렉터리 열기를 확인한다.
- 폴더 생성, 이름 변경, 복사·이동, 파일 열기, 삭제 확인을 제공한다.
- 기존 세션에 적용하려면 이미지 재생성과 앱 종료가 따르므로 사용자 세션을 일괄 교체하지 않는다.

완료 조건:

- xmonad와 openbox 모두에서 실행되고 한글 파일명·공백 경로를 처리한다.
- 세션 홈과 공유 Downloads의 소유권·권한이 유지된다.
- 웹에서 전송한 파일을 탐색기로 확인할 기반을 갖춘다. PC 파일 전송은 M6에서 한다.

## M6 — 웹 파일 패널과 업로드·다운로드

목표: M5의 탐색기로 관리하는 파일을 접속 PC와 주고받는다. M5 완료 후 진행한다.

- 웹에 디렉터리 탐색·파일 선택 패널을 두고 업로드·다운로드를 제공한다.
- 전송 범위는 Downloads로 제한하고, 이 폴더가 호스트에 있고 세션 사이에 공유된다는 사실을 화면에 표시한다.
- 대상 폴더 선택, 진행률, 취소, 한글 이름, 덮어쓰기 확인을 지원한다. 중단된 임시 파일을 완성 파일처럼 표시하지 않는다.
- 인증·CSRF·세션 소유권·generation을 확인하고 경로 이탈과 symlink를 통한 범위 밖 접근을 막는다.
- 파일 크기를 제한하고 나눠서 처리하며, 파일 전체를 웹 프로세스 메모리에 올리지 않는다.

완료 조건:

- PC에서 올린 파일을 M5 탐색기로 열고, 세션에서 만든 파일을 PC로 내려받아 hash가 일치한다.
- 대용량·전송 취소·권한 오류·경로 이탈·덮어쓰기·stale generation을 검증한다.
- 다른 사용자의 파일이나 허용 범위 밖 경로에 접근하지 못한다.

## M7 — 실행 상태를 유지하는 일시정지·이어하기

목표: 앱을 종료하지 않고 세션 실행을 멈췄다가 같은 상태로 이어간다. 일반 재시작과 구분해 UI 이름을 일시정지·이어하기로 한다.

- Docker pause/unpause로 구현하고 동작 전후에 소유권·generation·상태를 확인한다.
- 일시정지 전에 뷰어 연결을 정리한다. 정지 중의 새 VNC 연결·명령 실행·파일 변경은 상태 오류로 거부하고 이어하기 후 새로 연결한다. M3의 자동 재접속은 일시정지를 사용자 선택으로 보고 멈춘다.
- 화면과 status에 RAM 점유가 유지되고 재부팅에는 보존되지 않음을 표시한다. `run --host` 앱은 함께 멈추지 않고 네트워크 상대편의 연결 유지도 보장하지 않는다.
- 세션별 CPU·메모리와 뷰어 수(X11·웹 구분)를 표시하고 정지 상태를 오류나 종료로 표시하지 않는다.
- 앱 메모리가 사라지는 재시작은 별도 동작으로 두고 확인을 받는다.

완료 조건:

- 시험 프로세스의 PID와 RAM marker, 미저장 터미널·앱 입력을 유지하며 정지 중 연산이 멈췄다가 이어간다.
- 재개 후 noVNC, 파일 탐색기, Edge, kime가 동작하고 로그인 만료·삭제·중복 요청을 안전하게 처리한다.
- CPU 사용은 멈추고 RAM은 유지됨을 측정한다. 서버 재부팅 복원을 통과했다고 보고하지 않는다.

## M8 — 인증서 상태·내보내기·갱신

목표: 현재 인증서를 확인하고 교체하는 절차를 명령과 화면으로 제공한다.

- status와 웹 설정 화면에 대상 hostname/SAN, 만료일, 남은 기간, SHA-256 fingerprint를 표시한다.
- 공개 인증서를 내보내고 PC 신뢰 등록 절차를 안내한다. 개인 키는 내보내지 않는다. 최초 신뢰 확인은 SSH로 확인한 fingerprint를 기준으로 한다.
- self-signed 갱신과 준비된 인증서·키 가져오기를 제공한다. 키 일치, 유효 기간, origin hostname을 적용 전에 검사하고 백업·검증·적용·실패 시 복구 순서로 바꾼다. 포트 변경만으로 재발급하지 않는다.
- 교체 후 PC의 신뢰 등록을 갱신해야 함을 안내하고, 알림 없이 자동 교체하지 않는다.

완료 조건:

- 잘못된 키, 다른 hostname, 만료 인증서를 기존 설정 변경 없이 거부한다.
- 갱신·가져오기 후 HTTPS 로그인과 WebSocket이 동작하고 계정·데스크톱 데이터가 유지된다.
- 실패 시 이전 설정으로 복구되고, 로그와 공개 응답에 개인 키가 없다.

## M9 — 로그인 기기 목록과 접속 해제

목표: 어느 브라우저에서 로그인했고 어떤 화면 연결이 열려 있는지 확인하고 해제한다.

- 브라우저 정보, 로그인 시각, 마지막 활동, 만료 시각, 현재 기기 여부를 표시한다. SSH 터널에서 관측한 주소를 실제 접속 PC 주소로 단정하지 않는다.
- 특정 로그인과 전체 로그인을 해제하고, 그 로그인으로 열린 noVNC 연결도 닫는다.
- 로그인 cookie나 재사용 가능한 인증 token을 목록 API에 노출하지 않는다. 활동 기록의 범위와 보관 기간을 정하고 불필요한 브라우저 fingerprint는 수집하지 않는다.

완료 조건:

- 두 브라우저 로그인 중 하나만 해제하면 그 연결만 닫힌다.
- 전체 해제와 비밀번호 변경 후 기존 cookie·WebSocket으로 재접속할 수 없다.
- 현재 기기를 해제하면 로그인 화면으로 이동하고 세션 화면·clipboard 표시를 지운다.

## M10 — 세션 홈·웹 설정 백업과 복원

목표: 삭제나 이미지 변경 전에 사용자 파일과 운영 설정을 보존한다.

- 세션 홈, 시작 명령·창 관리자·해상도 등 메타데이터, 웹 설정을 백업한다. 공유 Downloads의 포함 여부를 명시하고 다른 세션의 데이터를 섞지 않는다.
- 앱을 종료한 상태에서 일관된 파일 백업을 만든다.
- 복원은 새 세션으로 하고 기존 세션을 덮어쓰지 않는다. 백업 형식·이미지 정보·hash·소유권을 검증한다.
- 백업은 소유자만 읽을 수 있다. 웹 계정 DB·TLS 개인 키가 든 운영 백업은 따로 표시하고 반출 시 암호화한다.
- 웹 설정을 복원하면 저장된 로그인 세션은 폐기한다. 비밀번호·인증서·주소의 복원 범위를 명시한다.

완료 조건:

- 파일 내용·권한·한글 경로와 선택한 메타데이터가 새 세션에서 복원된다.
- 손상된 archive, 경로 이탈, 다른 설치의 설정을 기존 데이터 손실 없이 거부한다.
- 복원한 웹 계정의 기존 cookie는 재사용되지 않는다.

## M11 — 디스크 checkpoint 가능성 검증

목표: 앱 메모리를 디스크에 저장해 RAM을 회수하고 재부팅 뒤 복원할 수 있는지 판정한다. 기능 구현 전의 검증 단계다.

- 공유 운영 서버가 아닌 별도 시험 환경에서 Docker·CRIU·kernel·cgroup·storage 조합을 기록한다. 운영 서버는 Docker experimental이 꺼져 있고 criu가 설치되어 있지 않으며, 시험을 위해 운영 Docker 설정이나 서버 패키지를 바꾸지 않는다.
- 작은 메모리 프로세스, Xvnc·창 관리자·D-Bus, 파일 탐색기, Edge·kime 순으로 확인한다.
- host network, 열린 TCP 연결, X socket, Chromium sandbox·shared memory, 열린 파일과 lock, 홈 volume·공유 Downloads의 파일 일관성을 검사한다.
- `run --host` 앱과 외부 연결은 checkpoint에 포함되지 않는다. 지원하지 않는 구성을 정의하고 저장 전에 탐지·거부할 방법을 정한다.
- checkpoint에는 메모리의 인증 정보도 들어가므로 저장 위치·권한·암호화·보존 정책을 정한다.

완료 조건:

- 지원 조합, 실패 조합, 필요한 운영 변경, 저장·복원 시간과 크기를 재현 가능한 기록으로 남긴다.
- M12 착수 여부를 판정한다. 지원 불가로 결론 나면 M12를 보류한다.
- 작은 프로세스 성공만으로 전체 데스크톱이 지원된다고 판단하지 않는다.

## M12 — 검증한 checkpoint의 저장·복원 기능

착수 조건: M11에서 지원 범위가 확인되고 필요한 운영 변경이 정해져 있어야 한다.

- 실행 상태를 저장하고 중지한 뒤, checkpoint와 짝지은 파일 상태를 검증해 복원한다.
- 새 요청과 뷰어를 막는 구간, 저장 완료, RAM 회수, 복원 준비, 실패 상태를 표시한다.
- 원격 서비스의 TCP 연결을 되살린다고 약속하지 않고 복원 후 재연결을 처리한다.
- 지원하지 않는 이미지·호스트 앱·외부 자원 조합과 포트 충돌은 저장·복원 전에 거부한다.
- 복원에 실패하면 원본 checkpoint와 백업을 남기고 기존 사용자 파일을 덮어쓰지 않는다.

완료 조건:

- 시험 호스트 재부팅 후 미저장 입력, RAM marker, 창 구성이 복원되고 noVNC로 다시 연결된다.
- 저장 후 실제 RAM이 회수되며, 앱 재시작이나 파일 복원을 checkpoint 성공으로 오인하지 않는다.
- 손상·호환성 불일치·포트 점유·복원 실패를 재현하고 원본 보존과 복구 절차를 확인한다.

## 진행 규칙

- 한 번에 한 마일스톤만 진행하고 다음 단계의 기능을 끼워 넣지 않는다.
- 기능 검증 → 구현 → 테스트 → 문서 순서로 진행하고 의미 단위로 커밋한다. push는 그때마다 요청받았을 때만 한다.
- 착수할 때 변경 범위, 완료 조건, 운영 영향과 복구 방법을 확인한다.
- 시험은 별도 설정·이름 붙인 시험 세션·별도 이미지로 한다. 사용자의 데스크톱을 시험 대상으로 삼지 않는다.
- 새 API에도 로그인·CSRF·Origin·소유권·generation 검사를 유지하고, 웹 컨테이너에 Docker socket을 주지 않는다.
- 끝나면 진행 순서의 체크와 완료 기록(날짜, 구현, 검증, 남은 제약)을 갱신한다.
