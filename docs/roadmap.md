# Raven 개발 마일스톤

기준일: 2026-11-02. 현재 동작하는 HTTPS/noVNC, 단일 계정 인증, 세션 생성·이름 변경·삭제·명령 실행을 기반으로 확장한다. 한 번에 하나의 마일스톤만 구현하고, 완료 조건을 검증한 뒤 다음 단계로 진행한다.

- [ ] M2 — 웹 doctor와 오류 진단
- [ ] M3 — 서비스 자동 기동과 연결 복구
- [ ] M4 — 양방향 텍스트 클립보드
- [ ] M5 — 세션 안의 파일 탐색기
- [ ] M6 — 웹 파일 패널과 업로드·다운로드
- [ ] M7 — 실행 상태를 유지하는 일시정지·이어하기
- [ ] M8 — 인증서 상태·내보내기·갱신
- [ ] M9 — 로그인 기기 목록과 접속 해제
- [ ] M10 — 세션 홈·웹 설정 백업과 복원

현재 진행: M1 완료. 다음 구현 대상: M2. 각 마일스톤은 기능 검증 → 구현 → 테스트 → 문서 작성 순서로 진행하고 의미 단위로 커밋한다. M12는 M11에서 지원 가능한 범위를 확인한 경우에만 착수한다. 미완료 마일스톤의 명령 이름과 화면 구성은 구현 예정안이다.

## 상태 보존의 의미

- 일시정지·이어하기: 같은 컨테이너 프로세스를 메모리에 유지한 채 실행을 멈췄다가 재개한다. 창, 미저장 입력, 프로세스 메모리를 유지하지만 RAM을 반납하지 않으며 서버 재부팅에는 유지되지 않는다. M7에서 제공한다.
- 종료·다시 시작: 프로세스를 종료하고 새로 실행한다. 파일은 남길 수 있지만 미저장 입력과 프로세스 메모리는 보존하지 않는다. 이것을 상태 복원으로 표시하지 않는다.
- 디스크 checkpoint·복원: 실행 메모리와 프로세스 상태를 디스크에 기록하고 복원한다. RAM 회수와 서버 재부팅 후 복원을 목표로 하되 실제 지원 여부는 M11에서 검증한다. 파일 상태도 checkpoint와 일치해야 한다.
- 파일 백업·복원: 세션 홈과 설정 파일을 보존한다. 프로세스 메모리 저장과 별도로 M10에서 제공한다.

Docker의 [pause](https://docs.docker.com/reference/cli/docker/container/pause/)와 [unpause](https://docs.docker.com/reference/cli/docker/container/unpause/)는 컨테이너 프로세스의 정지·재개 기능이다. [checkpoint](https://docs.docker.com/reference/cli/docker/checkpoint/)는 CRIU에 의존하는 experimental 기능이다. 현재 Raven의 `run --host` 앱은 컨테이너 밖의 프로세스이므로 같은 범위로 취급하지 않는다. [기존 호스트 앱 실행](../raven#L518), [세션 시작 절차](../rootfs/usr/local/bin/raven-entrypoint#L25)를 참고한다.

계획 작성 시 확인한 환경은 `docker info --format '{{.ExperimentalBuild}}'`의 `false`, `docker checkpoint --help`의 experimental 비활성 안내, `dpkg-query -W criu`의 패키지 미등록이다. 실제 checkpoint 생성·복원 시험은 아직 수행하지 않았다.

## M1 — 접속 설정 저장과 status 개선

목표: 서버 포트와 브라우저 주소를 구분하고, 재시작할 때 설정을 다시 추측하거나 입력하지 않게 한다.

- `raven web configure`에서 listen 주소, 서버 포트, 브라우저 origin을 관리한다. 웹 계정·세션·인증서 데이터는 보존한다.
- 기존 설치는 실행 중이거나 남아 있는 컨테이너의 실제 포트 매핑을 읽어 이전한다. 현재의 서버 9444와 브라우저 8443 조합을 기본 8443으로 덮어쓰지 않는다.
- 옵션 없는 `start`는 저장된 값을 사용한다. 명시적 변경은 사전 검사 후 성공한 값만 저장하고, 실패하면 이전 설정을 유지한다.
- `status`에 웹 컨테이너·중계 상태, 실제 listen 주소·포트, 브라우저 URL, 서버 주소, SSH 터널 명령, 실행 이미지, 로그 위치를 표시한다. 저장 설정과 실행 상태가 다르면 구분해서 보여준다.
- 서버 주소나 SSH 접속 대상을 확정할 수 없으면 추정값을 정답으로 출력하지 않는다. 필요한 입력을 명시한다.
- 포트 충돌과 유효하지 않은 origin을 변경 전에 검출한다. 현재 인증서의 SAN에 없는 hostname/IP 변경은 M8의 인증서 교체 경로와 함께 처리하며, 불일치 상태로 적용하지 않는다.
- 확인된 현재 상태를 읽는 `status`는 서비스를 시작하거나 설정·runtime 파일을 만들지 않는다.

완료 조건:

- 서버 포트와 브라우저 포트가 서로 다른 설치에서 출력된 터널 명령으로 로그인과 noVNC 접속이 된다.
- stop/start 후에도 포트와 origin이 유지되고, 계정·데스크톱 데이터가 보존된다.
- 포트 충돌, 초기화 전, 중계 종료, 컨테이너 시작 실패를 각각 정확히 표시한다.

완료 기록: 2026-11-02.

- 기능 검증: 기존 origin-only 설정과 실제 서버 9444 매핑을 확인했다. 이전 `start`는 포트를 저장하지 않았고 `status`는 runtime 파일을 만들었다.
- 구현: [호스트 CLI](../raven-web), [설정 저장](../web/raven_web/service_config.py). 현재 인증서와 일치하는 canonical origin만 허용하며, 기존 방식의 실행 중 컨테이너는 origin 변경 전에 중지한다.
- 테스트: 호스트 26개와 웹·설정 43개 통과. [설정 통합 시험](../tests/web_config_e2e.py)에서 설정 보존·이전·실패 복원을 확인했다. [화면 통합 시험](../tests/web_e2e.py)에서 서로 다른 포트의 TCP 전달 경로로 로그인·WSS·RFB와 웹 서비스 재시작 후 데스크톱 보존을 확인했다. 브라우저 로그인 폼 검사도 통과했다. 실제 접속 PC의 SSH 인증은 이 자동화 시험에 포함하지 않는다.
- 문서: [접속 설정 저장과 상태 확인](./web.md#접속-설정-저장)에 서버·브라우저·SSH 포트 구분, 이전·재시작·백업 절차를 기록했다.

## M2 — 웹 doctor와 오류 진단

목표: 사용자가 긴 Docker 명령이나 모호한 로그인 오류만 보고 원인을 추측하지 않게 한다. M1의 설정·상태 모델을 사용한다.

- `raven web doctor`에서 Docker 접근, 이미지, 데이터 volume 소유권, 계정 초기화 여부, 중계 socket, 실제 HTTPS 응답, origin·Host 일치, 인증서 대상·만료를 검사한다.
- 실패 항목마다 관측한 상태와 다음 조치를 표시한다. Docker 원본 오류도 보존하되 비밀번호·쿠키·개인 키·VNC credential을 출력하지 않는다.
- `status`는 현재 상태 요약, `doctor`는 실제 검사와 원인 설명을 담당한다.
- CSRF, 인증 실패, 로그인 대기 제한, 중계 장애를 구분한다. 잘못된 비밀번호와 존재하지 않는 계정은 외부에 같은 메시지로 응답한다.
- doctor는 계정 재설정, 데스크톱 시작, 설정 수정 또는 실제 로그인 시도를 수행하지 않는다.

완료 조건:

- 잘못된 포트·origin, 만료된 시험 인증서, 중계 종료, 권한 오류를 각각 재현해 진단 결과와 조치가 맞는지 확인한다.
- 로그·진단 출력에 인증 정보가 남지 않고, 실행 전후 사용자 설정과 세션 상태가 동일하다.

## M3 — 서비스 자동 기동과 연결 복구

목표: 서버 재부팅과 일시적인 통신 장애 뒤에도 사용자가 수동 복구를 반복하지 않게 한다.

- 사용자 단위 서비스로 호스트 중계와 웹 컨테이너의 시작·종료 순서를 관리한다. M1에 저장한 주소·포트를 사용한다.
- 로그인 전 부팅 시 실행이 필요한 환경에서는 user linger와 Docker 기동 순서를 확인한다. 공유 Docker 데몬이나 다른 사용자의 서비스를 변경하지 않는다.
- 중계 비정상 종료는 제한된 재시도로 복구하고 실패 원인을 M2에서 확인할 수 있게 한다.
- 브라우저는 일시적인 연결 실패 때 지연을 늘려 재접속한다. 매번 유효한 로그인 세션을 확인하고 새 VNC 접속 정보를 받는다.
- 로그아웃·인증 만료·세션 삭제에는 자동 재접속하지 않는다. 사용자가 연결을 종료하면 재시도를 취소한다.

완료 조건:

- 격리된 시험 호스트의 재부팅과 중계 프로세스 종료 뒤 저장된 주소로 접속할 수 있다.
- 네트워크 단절 후 화면이 복구되고, 로그아웃 뒤에는 재연결이 시도되지 않는다.
- 자동 복구가 데스크톱을 임의로 재시작하지 않는다. 호스트 재부팅 시 데스크톱 앱의 메모리 보존은 M12의 별도 범위다.

## M4 — 양방향 텍스트 클립보드

목표: 접속 PC에서 Raven으로, Raven에서 접속 PC로 텍스트를 복사한다.

- PC의 텍스트를 세션 clipboard로 보내는 붙여넣기 패널과, 세션에서 복사한 텍스트를 PC clipboard로 가져오는 버튼을 제공한다.
- 브라우저 권한이 허용되지 않으면 텍스트 영역에서 수동 복사·붙여넣기로 이어갈 수 있게 한다.
- 사용자 동작으로 전송하며, clipboard 내용을 로그·URL·브라우저 영구 저장소에 남기지 않는다. 로그아웃과 연결 종료 때 패널의 내용을 지운다.
- 첫 범위는 텍스트다. 이미지·파일 clipboard는 M6의 파일 전송과 구분한다.

완료 조건:

- 한글·영문·여러 줄 텍스트를 양방향으로 전달하고, xterm과 세션 브라우저에서 확인한다.
- 한 사용자가 여러 세션에 접속해도 선택한 연결의 clipboard로만 전달한다.
- 권한 거부, 연결 종료, 길이 제한 초과에서도 이유가 표시되고 민감한 내용이 남지 않는다.

## M5 — 세션 안의 파일 탐색기

목표: 파일 전송보다 먼저 Raven 데스크톱 안에서 파일을 찾아 열고 관리할 수 있게 한다.

- 가벼운 GUI 파일 관리자를 선정해 addon으로 제공한다. 앱별 설치를 core 이미지·호스트 패키지에 섞지 않는다.
- 메뉴와 런처에서 파일 탐색기를 열고 홈·Downloads로 이동할 수 있게 한다. 기본 파일 연결과 디렉터리 열기 동작을 확인한다.
- 폴더 생성, 이름 변경, 복사·이동, 파일 열기와 삭제 확인을 제공한다.
- 기존 세션에 addon을 적용하는 과정은 이미지 재생성과 앱 종료를 수반할 수 있으므로, 새 시험 세션으로 먼저 검증하고 사용자 세션을 일괄 교체하지 않는다.

완료 조건:

- xmonad와 openbox 모두에서 탐색기가 실행되고 한글 파일명·공백 경로를 처리한다.
- 세션 홈과 공유 Downloads의 소유권·권한이 유지된다.
- 웹에서 전송한 파일을 탐색기로 확인할 기반을 갖춘다. 이 단계 자체에는 PC 파일 전송을 넣지 않는다.

## M6 — 웹 파일 패널과 업로드·다운로드

목표: M5의 파일 탐색기로 관리하는 파일을 접속 PC와 주고받는다. M5 완료 후 진행한다.

- 웹에 디렉터리 목록·탐색·파일 선택 패널을 추가하고 업로드·다운로드를 제공한다.
- 첫 전송 범위는 기존 Downloads로 제한한다. 이 폴더가 호스트에 있고 세션 사이에 공유된다는 사실을 화면에 표시한다.
- 업로드 대상 폴더 선택, 진행률, 취소, 한글 이름, 덮어쓰기 확인을 지원한다. 중단된 임시 파일은 완성 파일처럼 표시하지 않는다.
- 인증·CSRF·세션 소유권·generation을 확인하고, 경로 이탈과 symlink를 통한 범위 밖 접근을 차단한다.
- 파일은 크기를 제한하고 일정한 크기로 나눠 처리한다. 파일 전체를 웹 프로세스 메모리에 올리지 않는다.

완료 조건:

- PC에서 올린 파일을 M5 탐색기로 열고, 세션에서 만든 파일을 PC로 내려받아 내용과 hash가 일치한다.
- 대용량·전송 취소·권한 오류·경로 이탈·덮어쓰기·stale generation을 검증한다.
- 다른 사용자의 파일이나 허용 범위 밖 경로에는 접근하지 못한다.

## M7 — 실행 상태를 유지하는 일시정지·이어하기

목표: 앱을 종료하지 않고 세션의 실행을 멈췄다가 같은 상태로 이어간다. 일반 restart와 구분해 UI 이름을 일시정지·이어하기로 정한다.

- Docker pause/unpause를 바탕으로 구현한다. 동작 전후에 소유권·generation·현재 상태를 확인한다.
- 일시정지 전에 뷰어 연결을 정리하고, 정지 상태에서는 새 VNC 연결·명령 실행·파일 변경을 명확한 상태 오류로 거부한다. 이어하기 후 새 연결을 만든다.
- M3의 자동 재접속은 일시정지 상태를 정상적인 사용자 선택으로 취급하고 재시도를 멈춘다.
- 화면과 status에 RAM 점유가 유지되고 서버 재부팅에는 상태가 보존되지 않는다는 점을 표시한다.
- `run --host` 앱은 함께 멈추지 않는다. 이 범위를 표시하고 임의의 호스트 프로세스까지 정지시키지 않는다. 네트워크 상대편의 연결 유지도 보장하지 않는다.
- 세션별 CPU·메모리와 연결된 뷰어 수를 표시한다. X11 뷰어와 웹 뷰어 수의 출처를 구분하고, 정지 상태를 오류나 종료 상태로 표시하지 않는다.
- 종료 후 새로 시작하는 작업을 추가할 경우 별도 재시작 동작으로 두고 앱 메모리가 사라진다는 확인을 받는다.

완료 조건:

- 시험 프로세스의 PID와 RAM marker, 미저장 터미널·앱 입력을 유지하며 정지 중 연산이 멈췄다가 이어간다.
- 재개 후 noVNC, 파일 탐색기, Edge, kime가 동작하고 로그인 만료·삭제·중복 pause/resume 요청을 안전하게 처리한다.
- CPU 사용은 멈추지만 RAM은 유지되는 것을 측정한다. 서버 재부팅 복원을 통과했다고 보고하지 않는다.

## M8 — 인증서 상태·내보내기·갱신

목표: 현재 인증서를 확인하고 교체하는 절차를 명령과 화면으로 제공한다. M1의 설정 변경과 M2의 진단을 확장한다.

- 대상 hostname/SAN, 만료일, 남은 기간, SHA-256 fingerprint를 status와 웹 설정 화면에서 확인한다.
- 공개 인증서를 파일로 내보내거나 다운로드하고, 접속 PC의 신뢰 등록 절차를 함께 안내한다. 개인 키는 공개 다운로드 대상에서 제외한다.
- 명시적인 self-signed 인증서 갱신과 관리자가 준비한 인증서·키의 가져오기를 제공한다. 인증서·키 일치, 유효 기간과 origin의 hostname을 적용 전에 검사한다.
- 설정과 인증서 교체는 백업·검증·적용·실패 시 복구 순서로 처리한다. 포트 변경만으로 인증서를 불필요하게 재발급하지 않는다.
- self-signed 인증서 교체 후에는 PC의 신뢰 등록을 갱신해야 함을 안내한다. 알림 없이 자동 교체해 기존 접속을 끊지 않는다.
- 웹의 다운로드는 편의 경로다. 최초 신뢰 확인은 인증된 SSH 연결에서 확인한 fingerprint를 기준으로 유지한다.

완료 조건:

- 잘못된 키, 다른 hostname, 만료 인증서는 기존 동작 중인 설정을 바꾸지 않고 거부한다.
- 갱신·가져오기 후 HTTPS 로그인과 WebSocket이 동작하고, 계정·데스크톱 데이터가 유지된다.
- 실패 시 이전 설정으로 복구할 수 있으며 로그와 공개 응답에 개인 키가 포함되지 않는다.

## M9 — 로그인 기기 목록과 접속 해제

목표: 현재 어느 브라우저에서 로그인했고 어떤 화면 연결이 열려 있는지 확인하고 해제한다.

- 브라우저 정보, 로그인 시각, 마지막 활동, 만료 시각과 현재 기기 여부를 표시한다. SSH 터널에서 관측한 주소를 실제 접속 PC 주소라고 단정하지 않는다.
- 특정 로그인과 전체 로그인을 해제한다. 해당 로그인에서 열린 noVNC 연결도 종료한다.
- 로그인 cookie 값이나 재사용 가능한 인증 token을 목록 API에 노출하지 않는다.
- 활동 기록의 범위와 보관 기간을 정하고, 불필요한 브라우저 fingerprint 수집은 하지 않는다.

완료 조건:

- 서로 다른 두 브라우저 로그인 중 하나만 해제하면 해당 연결만 종료된다.
- 전체 해제와 비밀번호 변경 후 기존 cookie·WebSocket으로 재접속할 수 없다.
- 현재 기기를 해제하면 로그인 화면으로 이동하고 세션 화면·clipboard 표시를 지운다.

## M10 — 세션 홈·웹 설정 백업과 복원

목표: 삭제나 이미지 변경 전에 사용자 파일과 운영 설정을 보존한다. M7의 실행 메모리 보존과 별도로 제공한다.

- 세션 홈, 시작 명령·창 관리자·해상도 등 메타데이터와 웹 설정을 백업한다. 공유 Downloads의 포함 여부를 명시하고 다른 세션의 데이터를 자동으로 섞지 않는다.
- 첫 버전은 앱을 종료한 상태에서 일관된 파일 백업을 만든다. 실행 중 상태를 보존하는 디스크 snapshot은 M11·M12에서 다룬다.
- 복원은 새 세션으로 먼저 수행하고 기존 세션을 덮어쓰지 않는다. 백업 형식·이미지 정보·hash·소유권을 검증한다.
- 백업은 기본적으로 소유자만 읽을 수 있게 한다. 웹 계정 DB·TLS 개인 키가 포함된 운영 백업은 별도로 표시하고 반출 시 암호화 방식을 제공한다.
- 웹 설정 복원 시 저장된 로그인 세션은 폐기한다. 비밀번호·인증서·주소 복원 범위를 명시한다.

완료 조건:

- 파일 내용·권한·한글 경로와 선택한 메타데이터가 새 세션에서 복원된다.
- 손상된 archive, 경로 이탈, 다른 설치의 설정을 기존 데이터 손실 없이 거부한다.
- 백업에 실행 메모리가 포함됐다고 표시하지 않으며, 복원한 웹 계정의 기존 cookie는 재사용되지 않는다.

## M11 — 디스크 checkpoint 가능성 검증

목표: 앱 메모리를 디스크에 저장해 RAM을 회수하고 서버 재부팅 뒤 복원할 수 있는지 판정한다. 제품 기능 구현 전에 수행하는 검증 단계다.

- 공유 운영 서버가 아닌 별도 시험 환경에서 Docker·CRIU·kernel·cgroup·storage 조합을 기록한다.
- 현재 호스트 패키지 설치 금지 규칙과 CRIU 요구사항을 함께 검토한다. 운영 Docker의 experimental 설정이나 서버 패키지를 시험을 위해 자동 변경하지 않는다.
- 작은 메모리 프로세스, Xvnc·창 관리자·D-Bus, 파일 탐색기, Edge·kime 순으로 확인한다.
- host network, 열린 TCP 연결, X socket, Chromium sandbox·shared memory, 열린 파일과 lock, 홈 volume·공유 Downloads의 파일 일관성을 검사한다.
- `run --host` 앱과 외부 연결은 컨테이너 checkpoint에 자동 포함되지 않는다. 지원하지 않는 구성을 정의하고 저장 전에 탐지·거부할 방법을 정한다.
- checkpoint에는 메모리의 인증 정보도 들어갈 수 있으므로 저장 위치·권한·암호화·보존 정책을 정한다.

완료 조건:

- 지원 조합, 실패 조합, 필요한 운영 변경, 저장·복원 시간과 크기를 재현 가능한 기록으로 남긴다.
- M12 착수 여부를 판정한다. 지원 불가로 결론 나면 M12를 보류하고 M7과 M10의 지원 범위를 유지한다.
- 사용자 세션이나 공유 Docker 데몬을 변경하지 않는다. 작은 프로세스 성공만으로 전체 Raven 데스크톱이 지원된다고 판단하지 않는다.

## M12 — 검증한 checkpoint의 저장·복원 기능

착수 조건: M11에서 지원 가능한 범위가 확인되고 필요한 운영 변경이 정해져 있어야 한다.

- 실행 상태를 저장하고 중지한 뒤, checkpoint와 짝지은 파일 상태를 검증해 복원한다.
- 새 요청과 뷰어를 차단하는 구간, 저장 완료, RAM 회수, 복원 준비, 실패 상태를 명확하게 표시한다.
- 원격 서비스의 TCP 연결까지 과거 상태로 되돌릴 수 있다고 약속하지 않는다. 복원 후 필요한 재연결을 처리한다.
- 지원하지 않는 이미지·호스트 앱·외부 자원 조합과 포트 충돌은 저장·복원 전에 거부한다.
- 복원 실패 시 원본 checkpoint와 백업을 남긴다. 검증 없이 삭제하거나 기존 사용자 파일을 덮어쓰지 않는다.

완료 조건:

- 시험 호스트 재부팅 후 미저장 입력, 프로세스의 RAM marker와 창 구성이 복원되고 noVNC로 다시 연결된다.
- 저장 후 실제 RAM이 회수되며, 일반적인 앱 재시작이나 파일 복원을 checkpoint 성공으로 오인하지 않는다.
- 손상·호환성 불일치·포트 점유·복원 실패를 재현하고 원본 보존과 복구 절차를 확인한다.

## 마일스톤 완료 규칙

- 한 시점에 하나의 마일스톤만 진행 상태로 둔다. 다음 단계의 기능을 함께 끼워 넣지 않는다.
- 착수 시 변경 범위, 완료 조건, 운영 영향과 복구 방법을 확인한다.
- 시험은 별도 설정·이름 붙인 시험 세션·별도 이미지로 수행한다. 사용자의 데스크톱을 시험 대상으로 삼지 않는다.
- 새 API에도 로그인·CSRF·Origin·소유권·generation 검사를 유지한다. 웹 컨테이너에 Docker socket을 주지 않는다.
- 필요한 테스트, 문서, 실제 사용 경로 검증을 마친 뒤 이 문서의 체크 항목과 구현 기록을 갱신한다.
- 완료 보고에는 구현 내용, 검증 결과, 남은 제약, 다음 마일스톤을 적는다. 이번 개발은 사용자 요청에 따라 의미 단위로 커밋한다. push는 해당 시점에 별도로 요청받았을 때만 수행한다.
